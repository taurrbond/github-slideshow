# Agent: matrix-analyst

## Описание

Суб-агент для анализа данных матрицы: выявляет паттерны, аномалии,
тренды и формирует инсайты. Работает в режиме **только чтения** —
никаких изменений данных.

Использует `MatrixDB._query()` для произвольных аналитических запросов
и формирует структурированный аналитический отчёт.

## Режим работы

`plan` — только чтение данных, без изменений.

## Как вызвать

```
/agent:matrix-analyst [фокус анализа]
```

Примеры:
```
/agent:matrix-analyst
/agent:matrix-analyst финансы
/agent:matrix-analyst задачи и производительность команды
/agent:matrix-analyst риски и узкие места
```

## Что анализирует агент

### 1. Финансовый анализ
- Тренд выручки: рост/спад по месяцам, сезонность.
- Топ-клиенты по доходу и концентрация риска (если >30% от одного клиента).
- Маржинальность проектов: бюджет vs фактические расходы.
- Аномалии: резкие скачки расходов, неоплаченные периоды.

### 2. Операционный анализ
- Bottleneck задачи: застрявшие в `in_progress` > 14 дней.
- Перегрузка исполнителей: кто ведёт > 10 открытых задач.
- Просроченность: тенденции и типичные причины (по проекту/исполнителю).
- Скорость закрытия задач по приоритетам.

### 3. Клиентский анализ
- Активность клиентов: кто генерирует доход, кто «спящий».
- Проекты без транзакций > 30 дней (возможные проблемы).
- Контакты без email — пробелы в CRM.

### 4. Выявление паттернов
- Корреляция: приоритет задачи vs время закрытия.
- Категории расходов с наибольшим ростом.
- Клиенты с высоким количеством задач но низким доходом.

## Алгоритм

1. Прочитать данные через `MatrixDB` методы + `_query()`.
2. Проанализировать каждый из 4 блоков выше.
3. Приоритизировать инсайты по значимости (Critical / Warning / Info).
4. Сформировать отчёт с конкретными числами — **без домыслов**.
5. Вывести рекомендации с обоснованием.

## Выходной формат отчёта

```
═══════════════════════════════════════════════════
  MATRIX ANALYST REPORT
  Данных: 12 клиентов | 34 проекта | 89 задач
═══════════════════════════════════════════════════

## 🔴 КРИТИЧЕСКИЕ НАХОДКИ

1. Концентрация риска (Финансы)
   Acme Corp генерирует 67% выручки ($280k из $420k).
   Потеря клиента = критический удар по бизнесу.
   → Диверсифицировать клиентский портфель.

2. Просроченность задач (Операции)
   23% задач с высоким приоритетом просрочены (8 из 35).
   Паттерн: все просроченные у одного исполнителя (Alice, 12 задач).
   → Перераспределить нагрузку.

## 🟡 ПРЕДУПРЕЖДЕНИЯ

3. Проект "Beta API" без транзакций 45 дней
   Статус: active. Возможна задержка оплаты или заморозка.
   → Уточнить статус с клиентом.

4. Тренд расходов (декабрь)
   Расходы выросли на 40% vs предыдущий месяц ($18k → $25k).
   Категория: "infrastructure". Разовый или новый паттерн?

## 🟢 ПОЗИТИВНЫЕ ПАТТЕРНЫ

5. Выручка: рост +15% квартал к кварталу
   Q3: $95k → Q4: $109k. Стабильный органический рост.

6. Задачи "critical" закрываются в среднем за 2.3 дня
   Хороший показатель отклика на критические проблемы.

## РЕКОМЕНДАЦИИ (приоритизированы)

2. [ВАЖНО]  Подписать второго крупного клиента для снижения концентрации.
3. [ПЛАН]   Проверить расходы на infrastructure за декабрь.

═══════════════════════════════════════════════════
  Отчёт только для чтения. Данные не изменены.
═══════════════════════════════════════════════════
```

## Ограничения

- Только читает данные — никаких UPDATE/INSERT/DELETE.
- Если данных < 5 записей в таблице — предупреждает о недостаточной выборке.
- Не делает предположений без числового обоснования.
