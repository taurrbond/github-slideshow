# CLAUDE.md — Правила проекта

## Общие принципы

- Читай этот файл при каждом старте сессии.
- Если контекст сжался (`/compact`), этот файл остаётся в памяти.
- Не превышай 200 строк в этом файле — держи его лаконичным.

## Самообучение через ошибки

**Если ты допустил ошибку при выполнении задачи:**

1. Признай ошибку явно.
2. Предложи конкретное обновление `CLAUDE.md` или навыка в `.claude/skills/`,
   которое предотвратит повторение.
3. Спроси подтверждение перед обновлением.

Пример формулировки:
> "Я допустил ошибку: [описание]. Предлагаю добавить в CLAUDE.md правило: [правило].
> Добавить?"

## Сохранение паттернов

**Все новые полезные паттерны, найденные в ходе работы, нужно сохранять в навыки.**

Критерии "полезного паттерна":
- Решение использовалось больше одного раза.
- Решение неочевидно и требует специфических знаний о проекте.
- Решение можно переиспользовать в будущих задачах.

Процедура:
1. Выяви паттерн по ходу работы.
2. После завершения задачи предложи: "Этот паттерн стоит сохранить в навык.
   Создать `.claude/skills/<name>/SKILL.md`?"
3. Создавай только после подтверждения.

## Рабочие соглашения

### Перед изменением кода
- Читай связанные файлы перед правкой — не угадывай структуру.
- Для крупных изменений используй `/agent:deep-refactor` для анализа.
- Для рефакторинга используй `/refactor` — он показывает план перед применением.

### Тесты
- Новая функция → всегда предлагай сгенерировать тесты через `/generate-tests`.
- Перед пушем убедись, что тесты проходят.
- Если тестов нет — предупреди явно перед любым рефакторингом.

### Безопасность
- Никогда не записывай секреты в файлы (`.env`, `secrets.json` защищены хуком).
- Не логируй чувствительные данные (токены, пароли, ключи).
- При обнаружении хардкода секретов — останови работу и сообщи.

### Git
- Коммиты — атомарные, одна логическая задача на коммит.
- Сообщение коммита: `<тип>: <что сделано>` (feat / fix / refactor / docs / chore).
- Не пушить без явной просьбы пользователя.
- Не создавать PR без явной просьбы пользователя.

## Структура проекта

```
.claude/
├── agents/
│   └── deep-refactor.md    # Архитектурный анализ (только чтение)
├── hooks/
│   └── pre-write.sh        # PreToolUse: защита .env, форматирование Python
├── skills/
│   ├── generate-tests/     # Генерация pytest / Jest тестов
│   └── refactor/           # Рефакторинг с планом и подтверждением
├── hooks.log               # Лог действий хуков (авто, не редактировать)
└── settings.json           # MCP-серверы и разрешения
```

## MCP-серверы

- `github` — работа с PR, issue, коммитами. Требует `GITHUB_TOKEN` в окружении.
- `context7` — документация библиотек прямо из чата.

## Запрещено

- Запись в `.env`, `secrets.json` и аналоги (заблокировано хуком).
- Применение изменений без плана при использовании `/refactor`.
- Создание коммитов или PR без явной просьбы.
- Удаление файлов без подтверждения.
